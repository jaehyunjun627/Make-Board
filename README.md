# 인스타그램 게시물 수집기 (Instagram Data Crawler)

이 프로그램에는 **서로 독립된 두 가지 기능**이 들어 있습니다.

| 기능 | 명령 | 하는 일 |
|------|------|---------|
| **A. 게시물 분석** | `from-json` / `crawl` | 계정 하나의 게시물별 참여 지표 → 엑셀(시트 3개) |
| **B. 경쟁사 팔로워 추적** | `track-followers` / `follower-report` | 여러 계정의 팔로워 수를 **매일 기록** → 성장 추이 엑셀 |

> **B는 게시물을 전혀 수집하지 않습니다.**
> 프로필을 열어 팔로워 숫자만 확인하고 바로 닫기 때문에,
> 매일 자동으로 돌려도 `result_*.xlsx` 같은 결과 파일이 쌓이지 않습니다.
> 자세한 내용은 **[7. 경쟁사 팔로워 추적기](#7-경쟁사-팔로워-추적기-track-followers)** 를 보세요.

아래 1~6번은 **A. 게시물 분석** 기능 설명입니다.

---

인스타그램 계정의 **게시물별 참여 지표**(좋아요·댓글·참여율)를 모아서
**시트 3개짜리 엑셀 파일**로 저장하는 파이썬 프로그램입니다.

| 시트 | 내용 |
|------|------|
| **게시물** | 게시물 목록 + 평균/최고치/최저치/표준편차 요약 |
| **주간 업로드** | 주 평균 업로드 횟수, 최다·최저 업로드 주간, 평균 업로드 주기, 주차별 상세 |
| **해시태그** | 많이 쓴 해시태그 TOP N, 떠오르는 해시태그, 전체 순위 |

여기에 더해 두 가지 자동 기록 기능이 있습니다.

| 명령 | 하는 일 | 결과물 |
|------|---------|--------|
| `track-followers` | 경쟁사 팔로워 수를 매일 기록 | `followers_history.csv` |
| `Daily_crawl` | 게시물이 올라온 뒤 **3일간** 좋아요·댓글 변화를 기록 | `Daily_crawl/계정이름.xlsx` |

파이썬 기초만 아셔도 그대로 따라 할 수 있게 설명했습니다.

## 1. 결과물 형태

결과 파일은 실행할 때마다 **`result_계정명_YYMMDDHHMM.xlsx`** 형태로 자동 생성됩니다.

```
result_bmwmotorradkorea_2608101634.xlsx   ← 2026-08-10 16:34에 bmwmotorradkorea 조회
```

언제 어느 계정을 조회한 결과인지 파일명만 봐도 알 수 있고, 실행할 때마다 이름이 달라져서
**이전 결과를 엑셀로 열어둔 채 다시 돌려도 충돌하지 않습니다.**
이름을 직접 정하고 싶으면 `--out 내파일.xlsx` 를 쓰세요.

> **엑셀 대신 CSV로 받고 싶다면** `--out 내파일.csv` 를 쓰세요.
> 시트마다 파일이 하나씩 만들어집니다 (`내파일.csv`, `내파일_주간업로드.csv`, `내파일_해시태그.csv`).
> `openpyxl` 이 설치돼 있지 않으면 자동으로 이 방식으로 저장됩니다.

### 시트 1 — 게시물

아래 8개 컬럼으로 만들어지고, **맨 위에 요약 통계 4줄**이 먼저 나옵니다.

| 구분 | 업로드일 | 좋아요 | 댓글 | 참여율(%) | 타입 | 본문 | 링크 |
|------|----------|--------|------|-----------|------|------|------|
| 평균 | | 703.5 | 24.8 | 1.46 | | | |
| 최고치 | | 1234 | 56 | 2.58 | | | |
| 최저치 | | 100 | 2 | 0.2 | | | |
| 표준편차 | | 436.9 | 20.9 | 0.92 | | | |
| | | | | | | | |
| | 2026-08-09 | 1234 | 56 | 2.58 | 이미지 | 오늘의 라이딩 코스 ... | https://instagram.com/p/ABC123/ |
| | 2026-08-05 | 980 | 31 | 2.02 | 릴스 | 신형 R1300GS 첫 시승기 ... | https://instagram.com/p/DEF456/ |

- **`타입`** 은 `이미지` / `릴스` / `캐러셀` 로 표시됩니다.
  여러 장짜리 글은 영상이 섞여 있어도 `캐러셀` 로 분류합니다.
- **`구분`** 칸은 요약 행에만 값이 들어갑니다. 게시물 행은 비어 있습니다.
- 요약과 게시물 사이에 **빈 줄**이 하나 들어가 눈으로 구분하기 쉽습니다.
- 인코딩은 **UTF-8 with BOM(`utf-8-sig`)** 이라 윈도우 엑셀에서 한글이 깨지지 않습니다.
- 게시물은 **날짜 내림차순(최신순)** 으로 정렬됩니다.
- 같은 게시물(`code` 기준)은 **중복 제거**됩니다.
- 본문의 **줄바꿈은 공백으로** 바뀝니다.
- 값이 없는 항목은 **빈 칸**으로 둡니다.

### 요약 통계 읽는 법

| 행 | 의미 |
|----|------|
| **평균** | 게시물당 평균 성과 |
| **최고치** | 가장 잘 된 게시물의 값 |
| **최저치** | 가장 저조한 게시물의 값 |
| **표준편차** | **성과 편차(consistency)**. 값이 작을수록 성과가 고르고, 클수록 게시물마다 들쭉날쭉하다는 뜻입니다. `최고치 - 최저치` 와 함께 보면 편차의 크기를 가늠할 수 있습니다. |

### 참여율(%)

```
참여율(%) = (좋아요 + 댓글) / 팔로워 수 × 100
```

팔로워 수는 **크롤링 시 프로필에서 자동으로** 가져옵니다. 터미널에 이렇게 표시됩니다.

```
[정보] 팔로워 수 확인: 125,430명 (참여율 계산에 사용)
```

자동으로 못 찾으면 참여율 칸은 비어 있고 안내 메시지가 나옵니다.
이때는 `--followers` 로 직접 넣어주세요.

```bash
python instagram_crawler.py from-json --followers 125430
```

> **공유·저장 컬럼은 제거되었습니다.**
> 공유수·저장수는 인스타그램이 **계정 소유자 본인에게만** (인사이트/Graph API) 공개하는
> 지표라 외부 수집으로는 항상 빈 칸이 나와, 컬럼 자체를 없앴습니다.
> 본인 소유의 비즈니스/크리에이터 계정이라면 Graph API `insights` 엔드포인트
> (`shares`, `saved` 지표)로 받아올 수 있습니다.

### 시트 2 — 주간 업로드

얼마나 자주, 얼마나 꾸준히 올리는지를 봅니다.

```
항목                    값                        비고
분석 기간               2026-02-13 ~ 2026-08-09   178일
전체 게시물 수          83
전체 주간 수            26                        게시물이 없는 주도 포함
주 평균 업로드          3.19                      회/주
최다 업로드 주간        2026-W21                  2026-05-18 ~ 2026-05-24 — 6회
최저 업로드 주간        2026-W07                  2026-02-09 ~ 2026-02-15 — 1회
평균 업로드 주기        2.16                      일 (게시물 사이 평균 간격)
중앙값 업로드 주기      1                         일 (극단값에 덜 흔들리는 값)

주차별 상세
주차        시작일(월)    종료일(일)    업로드 수
2026-W32    2026-08-03    2026-08-09    6
2026-W31    2026-07-27    2026-08-02    5
...
```

- **주 평균 업로드** 는 게시물이 하나도 없는 주까지 포함해서 계산합니다.
  그래야 "쉬는 주"가 평균에 제대로 반영되어 실제 빈도가 부풀지 않습니다.
- **평균 업로드 주기** 는 게시물 사이 간격의 평균입니다. 한 번씩 오래 쉬면 이 값이 크게 흔들리므로,
  **중앙값** 을 함께 보시면 평소 리듬을 더 정확히 알 수 있습니다.
- 주차는 ISO 기준이며 **월요일 시작** 입니다.

### 시트 3 — 해시태그

어떤 태그를 많이 쓰는지, 그리고 **요즘 뜨는 태그가 무엇인지** 봅니다.

```
가장 많이 쓴 해시태그 TOP 5
순위  해시태그        사용 횟수  사용 게시물 수  사용 비율(%)
1     #BMW            83         83              100
2     #BMWMotorrad    83         83              100
3     #모토라드        54         54              65.1

떠오르는 해시태그 (최근 90일 vs 그 이전 90일)
최근 게시물 64건 / 이전 게시물 19건 기준
해시태그        최근 90일  최근 사용률(%)  이전 90일  이전 사용률(%)  사용률 증감(%p)
#신형출시        45         70.3            0          0               +70.3
#R1300GS        42         65.6            0          0               +65.6
#BMWMotorrad    64         100             19         100             0.0
```

**떠오르는 해시태그를 '사용률'로 비교하는 이유**

단순 사용 횟수로 비교하면, 최근에 게시물을 많이 올렸다는 이유만으로 모든 태그가
"증가"로 보입니다. 위 예시에서 `#BMWMotorrad` 는 19회 → 64회로 늘었지만
**두 구간 모두 게시물 100%에서 쓰였으므로 실제 변화는 없습니다(0.0%p).**
그래서 게시물 수 대비 **사용률(%)** 로 비교하고, 그 증감(%p)이 큰 순으로 정렬합니다.
이렇게 하면 `#신형출시` 처럼 **새로 밀기 시작한 태그**가 정확히 위로 올라옵니다.

- 비교 기간은 `--trend-days` 로 조절합니다 (기본 90일 = 3개월). 1년치는 `--trend-days 365`.
- 수집 기간이 비교 기간의 2배보다 짧으면 "이전 구간"이 온전하지 않다는 경고가 함께 표시됩니다.
  제대로 보시려면 **비교 기간의 2배 이상** 을 수집하세요 (3개월 비교 → 6개월치 수집).
- 해시태그는 대소문자를 구분하지 않고 묶으며(`#BMW` 와 `#bmw` 는 같은 태그),
  화면에는 가장 많이 쓰인 표기로 보여줍니다.
- 한글·영문·숫자·밑줄 태그를 모두 인식합니다 (`#국내여행`, `#BMW_Motorrad`, `#2026년`).

## 3. 사용법

이 프로그램에는 명령이 5개 있습니다.

| 명령 | 하는 일 | 로그인 필요 |
|------|---------|------------|
| `from-json` | 이미 받아둔 JSON 파일 → 엑셀 변환 | ❌ |
| `login` | 브라우저로 로그인해서 세션 저장 (1회만) | — |
| `crawl` | 인스타그램에서 직접 게시물 수집 → 엑셀 | ⭕ (권장) |
| `track-followers` | 경쟁사 팔로워 수를 날짜별로 기록 (게시물 수집 안 함) | ⭕ (필수) |
| `follower-report` | 쌓인 팔로워 기록 → 성장 추이 엑셀 | ❌ |

### 방법 A. 이미 받아둔 JSON 파일로 분석 (가장 쉽고 확실함)

Apify 등에서 내려받은 `dataset_instagram-scraper_....json` 파일을
이 폴더에 넣고 실행하면 끝입니다.

```bash
# 폴더 안의 dataset_*.json 중 가장 최근 파일을 자동으로 찾아 변환
python instagram_crawler.py from-json

# 파일을 직접 지정하고 싶을 때
python instagram_crawler.py from-json "C:\Users\User1\Downloads\dataset_instagram-scraper_2026-08-10_05-52-38-972.json"

# 기간을 지정하고 싶을 때
python instagram_crawler.py from-json --start 2026-01-01 --end 2026-08-10

# 다른 이름으로 저장하고 싶을 때
python instagram_crawler.py from-json --out bmw_2026.xlsx

# 해시태그 TOP 10 + 1년 단위 트렌드로 보고 싶을 때
python instagram_crawler.py from-json --top 10 --trend-days 365
```

실행 결과 예시:

```
[정보] JSON 파일 자동 선택: dataset_instagram-scraper_2026-08-10_05-52-38-972.json
수집 120건 중 고유 118건 → 'result_bmwmotorradkorea_2608101634.xlsx' 저장 완료 (기간: 2026-01-03 ~ 2026-08-09)
```

### 방법 B. 인스타그램에서 직접 크롤링

**1단계 — 로그인 세션을 한 번 만들어 둡니다.**

```bash
python instagram_crawler.py login
```

크롬 창이 열리면 **직접 손으로 로그인**하세요(2단계 인증까지 완료).
피드가 보이면 터미널로 돌아와 `Enter` 를 누르면 `session.json` 이 생깁니다.
이 파일이 있으면 다음부터는 로그인 없이 바로 수집됩니다.

> `session.json` 에는 로그인 쿠키가 들어있습니다. **절대 공유하거나 깃에 올리지 마세요.**
> (`.gitignore` 에 이미 등록해 두었습니다.)

**2단계 — 수집합니다.**

```bash
# 기본 (최대 200건)
python instagram_crawler.py crawl https://www.instagram.com/bmwmotorradkorea/

# 올해 1월 1일부터 오늘까지
python instagram_crawler.py crawl bmwmotorradkorea --start 2026-01-01 --limit 500

# 작년(2025년) 자료만
python instagram_crawler.py crawl bmwmotorradkorea --start 2025-01-01 --end 2025-12-31 --limit 500

# 더 많이, 더 천천히 (차단이 걱정될 때)
python instagram_crawler.py crawl bmwmotorradkorea --limit 500 --delay 4

# 브라우저가 뭘 하는지 눈으로 보고 싶을 때
python instagram_crawler.py crawl bmwmotorradkorea --show-browser

# 원본 JSON도 함께 남기기 (나중에 재변환 가능)
python instagram_crawler.py crawl bmwmotorradkorea --save-json raw.json
```

계정은 URL(`https://www.instagram.com/이름/`)이든 아이디(`이름`)든 상관없습니다.

#### 과거 자료를 뽑을 때 (`--start` / `--end`)

- **`--limit` 은 "기간 안에 들어오는 게시물" 기준으로 셉니다.**
  작년 자료를 뽑을 때, 올해 게시물이 한도를 다 잡아먹지 않도록 하기 위함입니다.
- 다만 인스타그램은 **최신순으로만** 내려주므로, 과거로 갈수록 그 사이 게시물을
  전부 지나가야 합니다. 오래 걸릴 수 있으니 `--delay` 는 넉넉히 주세요.
- `--start` 를 주면 그보다 오래된 게시물이 3건 나온 시점에 자동으로 멈춥니다.
  (고정 게시물이 위쪽에 섞이는 경우를 감안해 여유를 둡니다.)
- 진행 상황은 이렇게 표시됩니다.
  ```
  [진행] 기간 내 42건 / 전체 확인 310건
  ```

## 4. 옵션 정리

### `from-json`
| 옵션 | 설명 | 기본값 |
|------|------|--------|

## 5. 코드 구조

`instagram_crawler.py` 한 파일이며, 역할별로 함수가 나뉘어 있습니다.

```
[A. 게시물 분석]
fetch_posts_from_json()  # JSON 파일에서 원본 게시물 읽기
fetch_posts_live()       # Playwright 브라우저로 직접 수집 (스크롤 = 페이지네이션)
  └ 스크롤할 때 인스타그램이 보내는 JSON 응답을 가로채서 수집
    (HTML을 파싱하는 방식보다 화면 개편에 훨씬 강합니다)
normalize_post()         # 도구마다 다른 필드 이름을 하나로 통일
find_follower_count()    # 참여율 계산에 쓸 팔로워 수 탐색
parse_data()             # 중복 제거 → 기간 필터 → 참여율 계산 → 최신순 정렬
build_summary_rows()     # 평균/최고치/최저치/표준편차 행 생성
build_weekly_sheet()     # 주간 업로드 빈도 분석
build_hashtag_sheet()    # 해시태그 순위 + 트렌드 분석
export_result()          # 엑셀(시트 3개) 또는 CSV 여러 개로 저장

[B. 경쟁사 팔로워 추적]  ← 게시물을 수집하지 않는 가벼운 기능
fetch_follower_count_live()   # 프로필을 열어 팔로워 수만 확인 (스크롤 없음)
  └ find_follower_count_for_user()  # '대상 계정'의 팔로워 수만 골라냄
  └ read_follower_count_from_dom()  # 응답에서 못 찾으면 화면에서 한 번 더 시도
load_accounts()               # accounts.csv 에서 추적할 계정 목록 읽기
load_history()                # followers_history.csv 읽기
calc_follower_change()        # 직전 기록 대비 증감·증감률 계산
track_followers()             # 수집 → 중복 확인 → 기록 → 로그 → 요약 출력
build_follower_report()       # 기록 → 시트 3개짜리 엑셀 리포트

main()                   # CLI 진입점
```

## 6. 자주 겪는 문제

**Q. `crawl` 을 돌렸는데 0건이 나옵니다.**
로그인 세션이 없거나 만료된 경우가 대부분입니다. `python instagram_crawler.py login` 을 다시 실행하세요.

**Q. 도중에 수집이 멈추거나 데이터가 안 늘어납니다.**
인스타그램의 요청 제한(rate limit)에 걸린 상태입니다. 프로그램이 자동으로 대기 시간을 늘리며
재시도하지만, 그래도 안 되면 `--delay 5` 처럼 간격을 늘리고 잠시 뒤 다시 실행하세요.

**Q. `PermissionError: [Errno 13] Permission denied` 오류가 납니다.**
저장하려는 CSV 파일을 **엑셀에서 열어둔 상태**입니다. 엑셀에서 그 파일을 닫고 다시 실행하세요.
기본 파일명은 실행할 때마다 시각이 붙어 달라지므로 보통은 이 오류가 나지 않지만,
`--out` 으로 같은 이름을 계속 쓰면 발생할 수 있습니다.

**Q. 12건만 수집되고 멈춥니다.**
인스타그램 프로필은 처음에 12건만 보여주고, 스크롤해야 다음 묶음을 불러옵니다.
스크롤이 안 먹는 상황이라면 `--show-browser` 로 실행해서 화면이 실제로 내려가는지 확인해 보세요.
그래도 안 되면 로그인 세션이 유효하지 않을 가능성이 큽니다. `login` 을 다시 실행하세요.

**Q. 엑셀에서 한글이 깨져요.**
결과 CSV는 `utf-8-sig` 로 저장되므로 보통은 안 깨집니다. 그래도 깨지면
엑셀에서 `데이터 → 텍스트/CSV 가져오기` 로 열고 인코딩을 **UTF-8** 로 선택하세요.

**Q. '떠오르는 해시태그'에 경고가 떠요.**
수집 기간이 비교 기간(기본 90일)의 2배보다 짧다는 뜻입니다.
3개월 트렌드를 제대로 보려면 6개월치를 수집하세요. (`--start` 를 넉넉히 주거나 `--limit` 을 늘리세요.)

**Q. 다른 계정의 게시물이 섞여 나와요.**
인스타그램은 프로필 화면에도 **'추천 게시물'** 로 남의 계정 글을 함께 내려줍니다.
프로그램이 게시물마다 주인을 확인해 조회 대상 계정의 글만 남기므로, 최신 버전에서는 섞이지 않습니다.
실행 중 이런 메시지가 나오면 정상적으로 걸러지고 있는 것입니다.

```
[정보] 다른 계정의 게시물 12건 제외: @royalenfield_korea(5건), @yamaha_kr(4건), ...
```

혹시 예전 버전으로 뽑은 결과가 있다면 다시 수집하세요. `git pull` 로 최신 코드를 받으시면 됩니다.

**Q. 참여율 칸이 비어 있어요.**
팔로워 수를 찾지 못한 경우입니다. `--followers 125430` 처럼 직접 지정하면 계산됩니다.

**Q. 공유·저장 항목은 어디 갔나요?**
외부 수집으로는 항상 빈 칸이라 컬럼을 제거했습니다. 위 "결과물 형태" 를 참고하세요.

## 7. 경쟁사 팔로워 추적기 (track-followers)

경쟁사 계정들의 **팔로워 수를 매일 기록**해서, 시간이 지날수록
"누가 얼마나 빨리 크고 있는지"를 볼 수 있게 만드는 기능입니다.

**게시물은 전혀 수집하지 않습니다.**
프로필 화면을 열어 팔로워 숫자만 확인하고 곧바로 닫습니다(스크롤 없음).
그래서 계정 10~30개도 빠르게 돌고, 매일 자동 실행해도 쓸데없는 파일이 쌓이지 않습니다.

### 7-1. 설치

게시물 분석 기능과 준비물이 같습니다. (**[2. 설치](#2-설치)** 참고)

```bash
pip install -r requirements.txt
python -m playwright install chromium
```

> 필요한 것: `playwright`(프로필 접속용), `openpyxl`(엑셀 리포트용)
> `openpyxl` 이 없으면 리포트는 자동으로 CSV 3개로 저장됩니다.

### 7-2. 최초 1회 — 인스타그램 로그인

팔로워 수는 로그인 상태에서만 안정적으로 보입니다. **처음 한 번만** 실행하세요.

```bash
python instagram_crawler.py login
```

크롬 창이 열리면 손으로 로그인하고(2단계 인증까지), 피드가 보이면
터미널로 돌아와 `Enter` 를 누르면 `session.json` 이 만들어집니다.
게시물 수집(`crawl`)과 **같은 세션 파일을 함께 씁니다.**

> 세션이 없거나 만료되면 팔로워 수를 **0으로 저장하지 않고**, 아래처럼 안내한 뒤 멈춥니다.
> ```
> [오류] 로그인 세션 파일('session.json')이 없습니다. 먼저 'python instagram_crawler.py login' 을 실행해 주세요.
> ```
> 보통 몇 주에 한 번 세션이 풀립니다. 그때 `login` 을 다시 실행하면 됩니다.

### 7-3. 경쟁사 계정 추가하기 — `accounts.csv`

`accounts.csv` 를 **메모장이나 엑셀로 열어** 추적할 계정을 적으세요.

```csv
account_name,username
혼다 모터사이클 코리아,honda_motorcycle_korea
BMW 모토라드 코리아,bmwmotorradkorea
로얄엔필드 코리아,royalenfield_korea
할리데이비슨 코리아,harleydavidsonkorea
트라이엄프 코리아,triumphmotorcycles_kr
```

| 칸 | 설명 |
|----|------|
| `account_name` | 결과에 보일 이름(한글 가능). 비워두면 아이디를 대신 씁니다. |
| `username` | 인스타그램 아이디 **또는** 프로필 주소 |

- `bmwmotorradkorea`, `@bmwmotorradkorea`, `https://www.instagram.com/bmwmotorradkorea/` **셋 다** 됩니다.
- **빈 줄**과 **`#` 으로 시작하는 줄**은 무시됩니다. 잠시 쉬고 싶은 계정은 앞에 `#` 만 붙이세요.
- 아이디 형식이 아닌 줄은 안내만 하고 건너뜁니다(전체가 멈추지 않습니다).
- 같은 계정을 두 번 적어도 한 번만 조회합니다.
- 파일 인코딩은 **UTF-8 with BOM(`utf-8-sig`)** 이라 윈도우 엑셀에서 한글이 깨지지 않습니다.
- 파일이 없으면 **예시와 함께 자동으로 만들어 줍니다.**

> ⚠️ 기본으로 들어있는 아이디는 **예시**입니다. 실제 계정 주소를 한 번 확인하고 고쳐 주세요.

### 7-4. 직접 실행하기

옵션은 전부 생략해도 되고, 필요하면 이렇게 씁니다.

### 7-5. 하루 한 번만 기록됩니다 (`--force`)

같은 날 여러 번 실행해도 **계정당 하루 한 줄**만 남습니다.
(컴퓨터를 하루에 여러 번 켜서 자동 실행돼도 기록이 부풀지 않습니다.)

```
[건너뜀] @bmwmotorradkorea 은 오늘 이미 기록했습니다.
```

오후에 한 번 더 확인하고 싶다면 `--force` 를 붙이세요.

```bash
python instagram_crawler.py track-followers --force
```

- 오늘 이미 있는 줄을 **덮어쓰지 않고**, 새 줄을 하나 더 추가합니다.
- 증감은 여전히 **직전 기록일(어제) 기준**으로 계산되므로 0이 되지 않습니다.
- 리포트에서는 하루에 여러 줄이 있으면 **그날의 마지막 기록**을 씁니다.

### 7-6. 기록은 어디에 쌓이나요 — `followers_history.csv`

프로젝트 폴더의 `followers_history.csv` 한 파일에 계속 **덧붙여** 쌓입니다.
**절대 덮어쓰지 않으므로** 과거 기록이 사라지지 않습니다.

```csv
date,timestamp,account_name,username,followers,daily_change,daily_change_rate
2026-09-03,2026-09-03 09:15:21,혼다 모터사이클 코리아,honda_motorcycle_korea,52100,,
2026-09-03,2026-09-03 09:16:05,BMW 모토라드 코리아,bmwmotorradkorea,48300,,
2026-09-04,2026-09-04 09:10:12,혼다 모터사이클 코리아,honda_motorcycle_korea,52340,240,0.46
```

| 컬럼 | 뜻 |
|------|-----|
| `date` | 기록한 날짜 (`YYYY-MM-DD`) |
| `timestamp` | 실제 수집 시각 (`YYYY-MM-DD HH:MM:SS`) |
| `account_name` | `accounts.csv` 에 적은 이름 |
| `username` | 인스타그램 아이디 |
| `followers` | 그 시점의 팔로워 수 |
| `daily_change` | 직전 기록일 대비 증감(명). 첫 기록이면 빈 칸 |
| `daily_change_rate` | 직전 기록일 대비 증감률(%), 소수 둘째 자리 |

```
daily_change      = 현재 팔로워 - 이전 팔로워
daily_change_rate = (현재 팔로워 - 이전 팔로워) / 이전 팔로워 × 100
```

함께 만들어지는 파일이 하나 더 있습니다 — **`tracker_log.csv`** (계정별 성공/실패 기록).

```csv
timestamp,account_name,username,status,message
2026-09-03 09:15:21,혼다 모터사이클 코리아,honda_motorcycle_korea,success,52340명 수집
2026-09-03 09:15:42,BMW 모토라드 코리아,bmwmotorradkorea,error,팔로워 수를 찾지 못했습니다.
```

`status` 는 `success`(기록함) / `skip`(오늘 이미 기록) / `error`(실패) 셋 중 하나입니다.
특정 계정이 자꾸 실패한다면 이 파일부터 열어 보세요.

### 7-7. 성장 리포트 만들기

```bash
python instagram_crawler.py follower-report
```

`follower_report.xlsx` 가 만들어집니다. (`--out 이름.xlsx` 로 이름 변경 가능)

| 시트 | 내용 |
|------|------|
| **일별 기록** | 날짜, 기록시각, 계정명, 아이디, 팔로워 수, 일간 증감, 일간 증감률(%) |
| **계정 요약** | 계정별 최신/이전 팔로워, 최근 증감, **7일·30일 증감과 증감률**, 최초·최신 기록일, 기록 일수 |
| **월별 성장** | 달마다 시작 팔로워 → 종료 팔로워, 순증감, 성장률(%) |

- **7일·30일 값은 그만큼 기록이 쌓였을 때만 계산합니다.** 자료가 모자라면
  틀린 숫자를 보여주는 대신 **빈 칸**으로 둡니다. (기록을 시작한 첫 주에는 비어 있는 게 정상입니다)
- 월별 성장은 그 달의 **첫 기록과 마지막 기록**을 씁니다.
- 리포트는 언제든 다시 만들 수 있습니다. `followers_history.csv` 만 있으면 되고,
  이 명령은 인스타그램에 접속하지 않습니다(로그인 불필요).

### 7-8. 매일 자동으로 돌리기 — 윈도우

`run_follower_tracker.bat` 을 **더블클릭**하면 바로 실행됩니다.
이 배치 파일은

1. 자기가 있는 폴더로 이동하고 (어느 폴더에서 실행하든 안전합니다)
2. 파이썬을 찾고 (`.venv` → `venv` → `env` → `python` → `py` 순서)
3. `python instagram_crawler.py track-followers` 를 실행하고
4. 화면 내용을 `logs\tracker_2026-09-03.log` 처럼 **날짜별 로그 파일**로 남깁니다.

> 개인 윈도우 사용자 이름(`C:\Users\...`)을 파일에 적어두지 않았기 때문에,
> 폴더를 다른 PC로 옮겨도 그대로 동작합니다.
> 옵션도 그대로 넘어갑니다. 예) `run_follower_tracker.bat --force`

#### 방법 A. 컴퓨터를 켤 때 자동 실행

1. 시작 메뉴에서 **작업 스케줄러**(Task Scheduler)를 검색해 엽니다.
2. 오른쪽에서 **작업 만들기…**(Create Task…)를 누릅니다. *(‘기본 작업 만들기’ 말고 이쪽입니다)*
3. **일반** 탭
   - 이름: `인스타 팔로워 추적`
   - **사용자가 로그온했는지 여부에 관계없이 실행** 선택 → 창이 안 뜨고 조용히 돌아갑니다.
   - **숨겨진 항목으로 실행** 체크
4. **트리거** 탭 → **새로 만들기…**
   - 작업 시작: **로그온할 때** (또는 **시작할 때**)
   - *팁: 부팅 직후에는 인터넷 연결이 아직 안 될 수 있으니*
     **지연 시간 지정**을 체크하고 **1분** 또는 **5분** 을 고르세요.
5. **동작** 탭 → **새로 만들기…**
   - 동작: **프로그램 시작**
   - 프로그램/스크립트: **찾아보기**로 `run_follower_tracker.bat` 선택
   - **시작 위치(옵션)**: 프로젝트 폴더 경로 (예: `C:\Users\내이름\Make-Board`)
     → 이 칸에는 **따옴표를 넣지 마세요.**
6. **조건** 탭
   - "컴퓨터가 AC 전원…" 체크 해제 (노트북이면 배터리에서도 돌게)
7. **확인** → 윈도우 로그인 암호를 물으면 입력합니다.

> 하루에 컴퓨터를 여러 번 켜도 괜찮습니다.
> **중복 방지 기능이 있어서 계정마다 하루 한 번만 기록됩니다.**
> 두 번째부터는 `[건너뜀]` 만 찍히고 몇 초 만에 끝납니다.

#### 방법 B. 매일 정해진 시각에 실행 (예: 오전 9시)

위 1~3번은 같고, **트리거** 탭만 다르게 설정합니다.

4. **트리거** 탭 → **새로 만들기…**
   - 작업 시작: **일정에 따라**
   - **매일** 선택 → 시작 시각을 **오전 9:00:00** 으로 지정
   - **컴퓨터가 꺼져 있어 놓친 작업은?**
     → **조건/설정** 탭에서 **예약 시간을 놓친 경우 가능한 대로 빨리 작업 시작** 을 체크하면,
       9시에 PC가 꺼져 있었어도 켜자마자 실행됩니다.
5. **동작** 탭은 방법 A와 동일 (`run_follower_tracker.bat`)

**잘 돌고 있는지 확인하는 법**

- `logs\` 폴더에 `tracker_날짜.log` 파일이 매일 생기는지 봅니다.
- `followers_history.csv` 에 날짜가 하나씩 늘어나는지 봅니다.
- 작업 스케줄러 목록에서 해당 작업의 **마지막 실행 결과**가 `0x0` 이면 정상입니다.

## 8. 매일 게시물 모니터링 (Daily_crawl)

팔로워 추적기가 "팔로워 수"를 매일 적는다면, 이 기능은 **"게시물이 올라온 뒤 3일 동안
좋아요·댓글이 얼마나 빨리 붙는지"** 를 계정마다 하나의 엑셀에 계속 쌓아 나갑니다.

```bash
python instagram_crawler.py Daily_crawl
```

---

### 8-1. 계정 이름은 어디에 넣나요 — `accounts.csv`

**팔로워 추적기와 똑같은 `accounts.csv` 파일을 그대로 씁니다. 따로 만들 필요가 없습니다.**

```csv
# 추적할 경쟁사 계정 목록입니다. 첫 줄(account_name,username)은 지우지 마세요.
account_name,username
BMW 모토라드 코리아,bmwmotorradkorea
로얄엔필드 코리아,royalenfield_kr
할리데이비슨 코리아,harley.korea
트라이엄프 코리아,triumphkoreaofficial
혼다코리아 모터사이클,hondamotorcyclekorea      ← 이렇게 한 줄 추가하면 끝
```

| 칸 | 무엇을 넣나 | 어디에 쓰이나 |
|----|------------|--------------|
| `account_name` | 사람이 읽는 이름 (한글·공백 가능) | **엑셀 파일 이름**이 됩니다 → `Daily_crawl/BMW 모토라드 코리아.xlsx` |
| `username` | 인스타그램 아이디 또는 주소 | 실제 크롤링에 쓰입니다 |

- `username` 은 아이디(`bmwmotorradkorea`) 든 주소(`https://www.instagram.com/bmwmotorradkorea/`) 든 됩니다.
- `#` 으로 시작하는 줄은 무시됩니다. **잠시 쉬고 싶은 계정은 앞에 `#` 을 붙이세요.**
- `account_name` 을 비워두면 아이디가 파일 이름이 됩니다.

---

### 8-2. 결과물 — 계정마다 파일 하나

날짜별로 파일이 늘어나지 않습니다. **계정당 엑셀 하나에 계속 덧붙습니다.**

```text
Daily_crawl/
├── BMW 모토라드 코리아.xlsx
├── 로얄엔필드 코리아.xlsx
├── 할리데이비슨 코리아.xlsx
└── 트라이엄프 코리아.xlsx
```

파일 안은 이렇게 생겼습니다.

| 계정 | 업로드일 | 타입 | 본문 | 링크 | 2026-09-07 좋아요 | 2026-09-07 댓글 | 2026-09-08 좋아요 | 2026-09-08 댓글 | 2026-09-09 좋아요 | 2026-09-09 댓글 |
|------|----------|------|------|------|---:|---:|---:|---:|---:|---:|
| BMW 모토라드 코리아 | 2026-09-07 | 이미지 | 오늘의 라이딩... | .../p/A1/ | 50 | 30 | 60 | 40 | 72 | 51 |
| BMW 모토라드 코리아 | 2026-09-08 | 릴스 | 신형 시승기... | .../p/B2/ | | | 100 | 20 | 130 | 25 |
| BMW 모토라드 코리아 | 2026-09-09 | 캐러셀 | 이벤트 안내... | .../p/C3/ | | | | | 80 | 10 |

- **게시물 하나 = 줄 하나.** 매일 실행해도 줄이 늘지 않고, 오른쪽에 날짜 칸만 채워집니다.
- 빈 칸은 "그날은 아직 그 게시물이 없었다" 또는 "그날 프로그램을 안 돌렸다"는 뜻입니다.
- 링크는 클릭하면 바로 열립니다.

---

### 8-3. 3일 스냅샷이란 무엇인가

게시물이 올라온 날부터 **3일 동안만** 좋아요·댓글을 기록하고, 그 뒤로는 건드리지 않습니다.

```text
D+0 = 올라온 날
D+1 = 다음 날
D+2 = 이틀 뒤
D+3 = 기록하지 않음 (창이 닫힘)
```

9월 7일에 올라온 글이라면 **9/7, 9/8, 9/9** 세 칸만 채워지고 9/10부터는 손대지 않습니다.

게시물마다 창이 따로 돕니다.

| 게시물 | 업로드일 | 기록되는 날짜 |
|--------|----------|--------------|
| A | 9/7 | 9/7, 9/8, 9/9 |
| B | 9/8 | 9/8, 9/9, 9/10 |
| C | 9/9 | 9/9, 9/10, 9/11 |

그래서 하루 실행할 때 **새 글만 보는 게 아니라, 아직 3일이 안 지난 예전 글도 함께 확인**합니다.
9월 9일에 돌리면 9/7 글(D+2), 9/8 글(D+1), 9/9 글(D+0)을 모두 갱신합니다.

> **왜 3일인가**: 콘텐츠 성과의 대부분은 업로드 직후에 결정됩니다.
> 3일이 지난 글까지 매일 다시 훑으면 인스타그램 요청만 늘고 얻는 정보는 거의 없습니다.

### 8-4. 매일 실행하기

```bash
# 오늘 날짜로 기록 (평소에는 이것만 쓰면 됩니다)
python instagram_crawler.py Daily_crawl

# 브라우저 창을 보면서 확인하고 싶을 때
python instagram_crawler.py Daily_crawl --show-browser

# 차단이 걱정되면 천천히
python instagram_crawler.py Daily_crawl --delay 4
```

윈도우에서는 배치 파일을 더블클릭하셔도 됩니다.

```text
run_daily_crawl.bat
```

**자동 실행 등록은 아래 파일을 한 번만 더블클릭하면 끝납니다.**

```text
작업스케줄러_등록_데일리크롤.bat
```

팔로워 추적기의 `작업스케줄러_등록.bat` 과 완전히 같은 방식이며, 작업 이름만 다릅니다.

| 등록되는 작업 | 언제 |
| --- | --- |
| `InstagramDailyCrawl-Logon` | 로그인하고 5분 뒤 |
| `InstagramDailyCrawl-Daily` | 매일 오전 09:30 |

**팔로워 추적기(09:00)와 30분을 벌려 둔 이유**는 둘 다 브라우저를 띄우기 때문입니다.
동시에 돌면 서로 느려지고 인스타그램 요청도 한꺼번에 몰립니다.

배치 파일이 자동으로 함께 켜 주는 설정 두 가지:

- **배터리로 켜져 있어도 실행** — 안 켜면 노트북을 안 꽂은 날은 통째로 건너뜁니다.
- **놓친 실행 보충** — 09:30에 PC가 꺼져 있었으면 켜자마자 대신 돌립니다.

이 두 개는 `schtasks` 명령만으로는 켤 수 없어서 배치 파일이 파워셸로 따로 넣어 줍니다.
실행이 끝나면 현재 상태가 표로 찍히는데, `Battery OK` 와 `Catch up` 이 둘 다 `True` 면 정상입니다.

> 로그온 작업과 매일 작업을 **둘 다 등록해도 게시물이 중복으로 쌓이지 않습니다.**
> `Daily_crawl` 은 게시물을 링크로 알아보고 이미 채워진 날짜 칸은 건드리지 않기 때문에,
> 하루에 몇 번을 돌려도 결과가 같습니다(8-6 참고).

등록이 잘 됐는지 확인하려면 파워셸에서:

```powershell
schtasks /query /tn InstagramDailyCrawl-Daily
```

`[ERROR] Registration failed` 가 뜨면 배치 파일을 **우클릭 → 관리자 권한으로 실행** 해 주세요.

### 8-5. 빠뜨린 날 채우기 — `--date`

`--date` 는 **"그날 관찰한 것처럼 기록하라"** 는 뜻입니다(기록일 지정).

```bash
# 9월 7일에 본 것처럼 기록
python instagram_crawler.py Daily_crawl --date 2026-09-07
```

- 그날 기준으로 창이 살아 있는 글(9/5~9/7 업로드)을 확인해 **9/7 칸**에 적습니다.
- 창을 벗어난 글은 건드리지 않습니다.

> **주의**: 지난 날짜를 지정해도 **지금 시점의 좋아요·댓글 수**가 적힙니다.
> 인스타그램은 과거의 좋아요 수를 알려주지 않기 때문입니다.
> 즉 하루 이틀 빠뜨린 걸 뒤늦게 메우면 실제보다 값이 높게 적힙니다.
> **정확한 추이를 보려면 매일 자동 실행을 걸어두는 것이 맞습니다.**

빠뜨린 날은 **빈칸으로 남습니다. 프로그램이 추정하거나 지어내지 않습니다.**

---

### 8-6. 이미 적힌 값 덮어쓰기 — `--force`

같은 날 두 번 실행해도 **이미 적힌 칸은 그대로 둡니다**(중복·덮어쓰기 방지).
수집이 중간에 실패해서 다시 채우고 싶다면 `--force` 를 붙이세요.

```bash
python instagram_crawler.py Daily_crawl --force
python instagram_crawler.py Daily_crawl --date 2026-09-07 --force
```

### 8-7. 옵션 정리

| 옵션 | 설명 | 기본값 |
|------|------|--------|
| `--date` | 기록일(스냅샷 날짜) `YYYY-MM-DD` | 오늘 |
| `--force` | 이미 적힌 칸도 다시 수집해 덮어씀 | 꺼짐 |
| `--accounts` | 계정 목록 파일 | `accounts.csv` |
| `--dir` | 엑셀을 저장할 폴더 | `Daily_crawl` |
| `--log-dir` | 실행 기록을 남길 폴더 | `logs` |
| `--session-file` | 사용할 로그인 세션 | `session.json` |
| `--limit` | 계정당 최대 확인 게시물 수 | `120` |
| `--delay` | 스크롤 사이 대기(초) | `2.0` |
| `--show-browser` | 브라우저 창 표시 | 꺼짐 |

| 표시 | 뜻 |

> 로그인이 끊겼는데 0건으로 조용히 넘어가는 일은 없습니다.

### 8-9. 자주 겪는 문제

**Q. `로그인 세션 파일이 없습니다` 라고 나옵니다.**
`python instagram_crawler.py login` 을 먼저 한 번 실행해 주세요. `track-followers` 와 같은 세션을 씁니다.

**Q. 엑셀 파일에 쓸 수 없다고 나옵니다.**
그 파일을 엑셀에서 열어둔 상태입니다. 닫고 다시 실행하세요.

**Q. 같은 게시물이 두 줄로 나뉘었습니다.**
설계상 생기지 않습니다. 게시물은 **주소의 고유 코드(shortcode)** 로만 구분하며,
본문이나 업로드일이 같아도 코드가 다르면 다른 글, 코드가 같으면 무조건 같은 줄입니다.
만약 실제로 생겼다면 알려주세요.

**Q. 어제 글이 안 잡힙니다.**
`--limit` 이 작으면 최신 글만 보고 멈출 수 있습니다. 게시물이 많은 계정이라면 `--limit 200` 정도로 올려보세요.

**Q. 팔로워 추적기와 같이 돌려도 되나요?**
됩니다. 서로 다른 파일에 기록하므로 충돌하지 않습니다.
다만 **동시에 돌리면 인스타그램 요청이 몰리므로**, 작업 스케줄러에서 10~20분 정도 시간을 벌려 두시길 권합니다.

## 9. 이용 시 유의사항

- 공개된 계정의 공개 게시물 정보를 수집하는 용도로 만들어졌습니다.
- 인스타그램 이용약관과 `robots.txt`, 그리고 개인정보 보호 관련 법령을 지켜 주세요.
- 짧은 시간에 과도하게 요청하면 계정이 일시 제한될 수 있습니다. `--delay` 를 넉넉히 주세요.
- 본인 계정 데이터를 안정적으로 받는 가장 정석적인 방법은
  [Instagram Graph API](https://developers.facebook.com/docs/instagram-api) 입니다.
